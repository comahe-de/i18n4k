# i18n4k — example-compose (Kotlin Toolchain)

Standalone Kotlin Toolchain port of
[`../../examples/example-compose`](../../examples/example-compose): a Compose
Multiplatform application that demonstrates i18n4k features such as typed
parameters, plural/ordinal selection, message attributes and value types.

| Module | Product | Description |
|---|---|---|
| `shared` | `kmp/lib` | Compose UI, platform abstraction, message bundles and generated i18n code (JVM, Wasm JS, Android, iOS). |
| `desktopApp` | `jvm/app` | Compose Desktop application. |
| `webApp` | `wasm-js/app` | Compose Multiplatform browser application (Kotlin/Wasm). |
| `androidApp` | `android/app` | Android application. |
| `iosApp` | `ios/app` | iOS application (requires macOS/Xcode). |
| `plugins/i18n4k` | `jvm/amper-plugin` | The i18n4k Kotlin Toolchain plugin. |

The module structure follows the one generated by `kotlin init` for a Compose
Multiplatform app.

Because the Kotlin Toolchain cannot publish custom plugins yet, the plugin is a
thin local wrapper around the published `i18n4k-generator` library. See
[`plugins/i18n4k`](plugins/i18n4k) and
[`doc/kotlin-toolchain-plugin.md`](../../doc/kotlin-toolchain-plugin.md).

## Prerequisites

The project uses the published `de.comahe.i18n4k:*:0.11.2` artifacts. To test
locally built versions, publish them first from the repository root:

```sh
./kotlin publish mavenLocal
```

`plugins/i18n4k/module.yaml` contains `mavenLocal`; Maven Central is the
Toolchain default. Remove `mavenLocal` if you want to make sure only released
artifacts are used.

## Build and run

Run the commands from this directory (`examples-kotlin-toolchain/example-compose`).
On Windows use `./kotlin.bat`; the shell wrapper cannot run under PowerShell.

```sh
./kotlin build                     # all modules supported on this host
./kotlin test -m shared -p jvm     # i18n/translation tests
./kotlin run -m desktopApp         # Compose Desktop (Compose Hot Reload)
./kotlin run --no-compose-hot-reload -m desktopApp   # plain run, regular JDK
./kotlin run -m webApp             # Kotlin/Wasm app in a browser
./kotlin run -m androidApp         # installs on a device/emulator, provisions the SDK
./kotlin run -m iosApp             # macOS + Xcode only
```

For Compose-enabled JVM apps, `kotlin run` enables Compose Hot Reload by default
and downloads a JetBrains Runtime. Use `--no-compose-hot-reload` to start the
app with the regular JDK instead (the example does not require Hot Reload).

`./kotlin build` builds the Android and web apps on every host, and the iOS app
only on macOS. Running the iOS module requires Xcode and a first `xcodebuild
-runFirstLaunch`.

## i18n4k plugin

The plugin is enabled in [`shared/module.yaml`](shared/module.yaml):

```yaml
plugins:
  i18n4k:
    enabled: true
    sourceCodeLocales:
      - en
      - en_US
      # ... plus en_US_texas, de, fr, nl and the attribute locales
    valueTypeMapping:
      LS: de.comahe.i18n4k.strings.LocalizedString
```

The bundles live in [`shared/src/i18n/x/y`](shared/src/i18n/x/y). Unlike the
Gradle example, **all locales are inlined into the generated Kotlin code**
(`sourceCodeLocales`). The Gradle plugin writes the non-inlined language files
into `composeResources/files/i18n` so that Compose resources can load them; the
Toolchain plugin writes its outputs below the task output directory, and those
cannot be wired into `composeResources` from a plugin. Inlining everything keeps
the example self-contained and works identically on all platforms. The
resource-file variant is shown by
[`../example-mpp`](../example-mpp).

The generated Kotlin sources are contributed through `generated.sources`, so
they are compiled, packaged and shown in IntelliJ IDEA. Messages and attributes
are used in [`shared/src/example/compose/App.kt`](shared/src/example/compose/App.kt).

Commands:

```sh
./kotlin do generateI18n4kFiles -m shared
./kotlin do clearI18n4kFiles -m shared
```

See [`doc/kotlin-toolchain-plugin.md`](../../doc/kotlin-toolchain-plugin.md) for
the full settings reference and limitations.

## Differences from the Gradle example

* The Gradle project has a single `composeApp` module plus an `androidApp` and
  an Xcode project. The Toolchain project splits this into a shared `kmp/lib`,
  one module per platform app and a re-usable Compose resources folder inside
  `shared`.
* Compose resources are enabled through `settings.compose.resources` and live in
  `shared/composeResources`; the generated accessors are in
  `example.compose.resources` (configured via `packageName`).
* Translations are inlined instead of loaded from `composeResources/files`
  (see above).
* Compose Hot Reload is not configured in this example.
